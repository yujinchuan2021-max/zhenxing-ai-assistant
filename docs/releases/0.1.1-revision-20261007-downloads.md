本轮对外仍为 **0.1.1 公开预览版**，内部修订号为 `0.1.1.1`，用于区分此前的 `0.1.1.0`。修订集中处理官网下载、云端工具目录、完整文件校验与真实安装状态。客户端和服务端具备明列备用源的校验能力；官网直连不代表已部署大陆 CDN 或独立备用线路。

本轮源码与完整客户端包已完成构建和本地校验，GitHub 发布附件、官网下载文件、程序更新清单、云端工具目录、新增资源及官网页面均已完成发布与对应回读验收。下文记录本轮实际结果，并保留第一阶段检查历史。

## 客户端行为

- 客户端安装包从官网的正式下载地址获取，无需先访问 GitHub。下载大小、SHA-256 与完整 ZIP 信息必须匹配；程序更新仍是下载、校验后手动关闭旧版、完整解压到新文件夹并启动，不会自动替换或重启。
- 社区工具页默认使用“枕星下载”，读取已有自有目录及本地缓存。当前平台有便携包的工具才进入这个直接下载列表；GitCode/GitHub 社区仍作为主动选择的来源保留。
- 自有目录卡片、应用中心和已能准确识别身份的旧工具卡使用同一云工具管理器。映射按稳定 ID 或完整旧安装目录边界进行，不按相似名称猜测产品或版本。
- 下载窗口自动选择自有来源。schema2 支持一个主源和最多三个明列备用源，每次尝试使用新的下载及解压目录，重新核验大小、SHA-256、ZIP 条目 CRC 和主入口。用户取消会停止尝试，失败不提交安装。
- 新客户端优先请求 v2 目录；未部署或未发布而返回 404/501 时回退既有 v1。错误的 200 响应、鉴权失败和服务故障不被当成正常目录。既有目录缓存与修订递增校验保留。
- 主动选择旧社区来源时，网页伪装 ZIP、缺失指定主程序、损坏 ZIP 或声明文件哈希不符会被拒绝；尝试其明列其他来源。验证后才替换目录，不再先删除旧工具。失败残留和辅助 EXE 不因目录非空而显示“已安装”。
- 应用中心以检测到的实际软件入口和下载、安装结果显示状态。打开来源网站、用户标记完成或目录中只有部分文件，不作为安装和服务连接已验证的证据。

## 服务端准备（第一阶段候选记录）

新目录发布必须完整验收每个声明的真实主备文件。任何文件失败都不切换当前目录。验收回执绑定整个规范化目录，并和修订、不可变来源绑定及当前指针一起提交。

v1 与 v2 分别维护目录和历史；第一次 v2 修订必须超过 v1 当前修订及客户端内置种子修订。管理员不能用本机回执跳过服务器的验收。

实现与部署步骤见[国内工具分发说明](../tool-distribution.md)。第一阶段记录冻结时，新增服务源码、v2 公网路由以及独立备用存储尚未部署；后续生产变更需另附真实验收记录。允许的备用域名不等于已上线来源。

## 第一阶段真实文件检查（保留历史）

第一阶段对当时生产目录 revision 2 的全部 70 个唯一主源 ZIP 完整下载，共 314,561,687 字节。70 个包均通过大小、SHA-256、全条目 CRC 与安全路径检查，82 个声明入口通过 PE 与架构检查。没有执行厂商程序，也没有把这些结果视为全国网络、功能、依赖或安装完成的保证。

该阶段目录共 111 个工具，另 41 个没有受管便携包，不在其整包检查范围内。Dism++ 等旧社区条目的缺失文件需以取得并验收的真实包补齐；本修订不会把目录文字当成安装完成。新增包和安装器的最终数量、来源许可、校验值与上线状态以本轮后续验收记录为准。

桌面安装器、驱动及 winget/npm/pip 依赖是另一类安装流程。部分入口仍使用第三方来源；本轮不能宣称所有 AI 软件或驱动均已改为国内独立分发。
