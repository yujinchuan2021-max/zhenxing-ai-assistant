# 0.1.1 下载可靠性修订（2026-10-07）

本轮保持客户端版本 `0.1.1.0`，修订目标是收敛下载入口、阻止网页或损坏文件被当成工具安装，并为国内独立主备分发准备客户端和发布服务。

## 客户端行为

- 社区工具页默认使用“枕星下载”，读取已有自有目录及本地缓存。当前平台有便携包的工具才进入这个直接下载列表；GitCode/GitHub 社区仍作为主动选择的来源保留。
- 自有目录卡片、应用中心和已能准确识别身份的旧工具卡使用同一云工具管理器。映射按稳定 ID 或完整旧安装目录边界进行，不按相似名称猜测产品或版本。
- 下载窗口自动选择自有来源。schema2 支持一个主源和最多三个明列备用源，每次尝试使用新的下载及解压目录，重新核验大小、SHA-256、ZIP 条目 CRC 和主入口。用户取消会停止尝试，失败不提交安装。
- 新客户端优先请求 v2 目录；未部署或未发布而返回 404/501 时回退既有 v1。错误的 200 响应、鉴权失败和服务故障不被当成正常目录。既有目录缓存与修订递增校验保留。
- 主动选择旧社区来源时，网页伪装 ZIP、缺失指定主程序、损坏 ZIP 或声明文件哈希不符会被拒绝；尝试其明列其他来源。验证后才替换目录，不再先删除旧工具。失败残留和辅助 EXE 不因目录非空而显示“已安装”。

## 服务端准备

新目录发布必须完整验收每个声明的真实主备文件。任何文件失败都不切换当前目录。验收回执绑定整个规范化目录，并和修订、不可变来源绑定及当前指针一起提交。

v1 与 v2 分别维护目录和历史；第一次 v2 修订必须超过 v1 当前修订及客户端内置种子修订。管理员不能用本机回执跳过服务器的验收。

实现与部署步骤见[国内工具分发说明](../tool-distribution.md)。新增服务源码、v2 公网路由以及独立备用存储尚未在本轮部署；允许的备用域名不等于已上线来源。

## 本轮真实文件检查

对当前生产目录 revision 2 的全部 70 个唯一主源 ZIP 完整下载，共 314,561,687 字节。70 个包均通过大小、SHA-256、全条目 CRC 与安全路径检查，82 个声明入口通过 PE 与架构检查。没有执行厂商程序，也没有把这些结果视为全国网络、功能、依赖或安装完成的保证。

原目录共 111 个工具，另 41 个没有受管便携包，不在此次整包检查范围内。Dism++ 的旧社区 ZIP 缺失问题不能靠切换不存在的源解决，需另行取得并发布真实包；本修订不会把目录文字当成安装完成。

桌面安装器、驱动及 winget/npm/pip 依赖是另一类安装流程。部分入口仍使用第三方来源；本轮不能宣称所有 AI 软件或驱动均已改为国内独立分发。

本轮提供本地候选构建供核对。正式下载附件、官网包和程序更新清单的上线状态应以各自实际发布记录为准；同为 0.1.1 的修订不能只凭版本号认为已自动替换。
