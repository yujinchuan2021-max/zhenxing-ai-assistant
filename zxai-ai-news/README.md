# 枕星 AI 资讯服务

提供中文 AI 媒体资讯与厂商、研究机构 RSS/Atom 更新。服务器可用独立配置的模型统一生成中文标题、短摘要、分类及重点资讯，保存后供所有读者读取；客户端个人 AI 可额外做个性化整理。读者不需要配置 AI 账号。服务器编辑不读取客户端配置、用户 Key 或对话。

Python 3.10+，无第三方运行依赖。`python server.py --port 8769 --data ./feed-cache.json` 启动，仅监听 localhost；`--once` 可收集一次并保存缓存。首次刷新完成前列表返回 503；默认每天北京时间 09:00 自动刷新固定来源，各源失败独立保留原成功时间，72 小时后旧源不再展示。保留近 120 天发布的更新，未知发布日期原样为 null、排在末尾。

首页按真实发布时间排列，不因中文、编辑完成或重复抓取改变日期。中文来源摘要最多180字、其他来源240字；编辑输入使用来源原始标题和最多1200字的摘要片段，不抓文章全文。未配置服务器模型、资料不足、额度耗尽或编辑失败时保留来源资讯；不会伪造中文摘要、精选、热度或趋势。Codex/OpenCode 仅保留有实际说明的非预发布更新，每个工具最多一条；alpha/beta/rc/nightly等与空说明的版本号不发布。质量过滤也应用于旧缓存，刷新失败不会重新发布旧噪声。综合科技与研究来源过滤AI主题，企业案例归行业、指南归技巧。可用来源筛选后无条目返回200空列表；所有来源均不可用时返回503。

去重仅合并去掉明确追踪参数后相同的原文URL，保留真实来源归属；不同版本、相似标题不会凭猜测合并成事件。当前不发布热点分数、趋势、日报或全网热度。

RSS/Atom优先读取标准命名空间的文章字段，不使用media扩展的图片/视频说明冒充摘要。展示截取优先在句末或词边界结束，并标明省略；摘要缺失时保留原文入口，不补写事实。相同条目刷新保留首次发现时间，内容没有改变时不因采集时间更新而使分页游标失效。

反向代理：`/api/ai-news/` 对应 localhost:8769 `/`，公开 GET `/api/ai-news/v1/items?mode=all&limit=20`。支持 category/q/cursor，最多 50 条；内容刷新造成 cursor 过期时返回 409，客户端点击刷新回到第一页。`/health` 用于运行检查。没有写入、投稿或管理接口。

只读取来源 feed 的标题、链接、时间和提供的摘要片段；不抓取文章全文。UI 提供来源、原文入口、摘要缺失说明和 AI 整理标记。缓存文件只含公开资讯。新增来源需修改固定清单，外部请求不能注入采集地址。

信息流与编辑分层的设计参考 [AIHOT](https://github.com/KKKKhazix/AIHOT) 开源工程（MIT）。此目录为独立实现，没有调用 AIHOT 托管服务，没有复制其源码、托管资讯库、品牌或图片，无额外框架或数据库运行依赖。

离线验证：`python -m unittest discover -s tests -v`。不得用真实用户 API Key 运行验证。

## 网页门户

`portal/` 是枕星自有资讯门户，使用 HTML/CSS/JavaScript，无额外构建依赖。服务固定提供 `/portal/`、`/portal/portal.css` 与 `/portal/portal.js`；反向代理 `/ai-news/` 到 localhost:8769 `/portal/`。独立浏览器使用同源 `/api/ai-news/v1/items`，没有 AI 配置也可搜索、按分类阅读、分页与打开原文。

客户端 WebView2 打开同一个门户，网页发有限的资讯查询消息，原生会话读取服务器更新并复用全局 AI 配置生成可选摘要。网页只接收公开新闻、界面语言与主题；不接收 Key、接口配置或工具执行接口。浏览器读取已发布内容，不在浏览、搜索、分页时调用模型。返回页面保留内容、搜索草稿和阅读位置。顶部仅在实际编辑精选/个人精选存在时标为重点；否则是按时间排序的“新近资讯”。客户端源码已传递独立的serverEdited/selected/reason字段，并保留个人AI摘要的原有标记；旧体验包能读取服务端中文标题和摘要，但没有传递新增元数据时只展示新近资讯。

## 独立服务器编辑配置

部署使用 `/etc/zxai-ai-news/editorial.env`（0600，服务器root维护），新闻服务专用drop-in只引用该文件。模板为 `editorial.env.example`，默认关闭且Key为空；使用提供Chat Completions的兼容服务，JSON mode及token参数字段可按服务显式配置，并纳入编辑版本。填入服务器专用 `BASE_URL / MODEL / API_KEY` 后设置 `ENABLED=1`，重启 `zxai-ai-news.service`。不要把Key发送到聊天或写进源码。

默认每轮4篇、每小时12次、UTC每日96次，每篇最多800输出tokens，处理最近14天且摘要充分的资讯。调用次数在请求前写入原子账本，失败也计入；这控制请求量，不等于精确费用预算。后台固定每天北京时间09:00采集并整理，由既有服务内的单一写入线程执行；访问网页不会触发调用。编辑缓存绑定原始内容、模型/端点与提示词版本，重启复用结果，不重复付费。明确402/401/403会持久暂停；问题解决后由管理员更改RESUME再重启，禁止自动测余额。429会全局冷却30分钟；超时、中断、不合格JSON不会对同一内容自动重复请求。缓存损坏会停用编辑并保留来源资讯，不能清空账本后自动重新付费。

发布前校验结构、中文、证据原句、数字/版本及拉丁实体，拒绝生成网址；精选由合格评分达到75后产生。此类检查不能证明所有中文语义忠实，实际接入模型后仍需抽样核对摘要质量。原文ID、来源、链接、发布时间不被模型修改；编辑不刷新来源抓取时间。日更服务的缓存最多保留72小时，页面仍展示实际来源时间，避免下一天更新时出现空窗。

## 每日自动更新

`--daily-at 09:00` 为默认北京时间。服务自动运行，不需要Codex窗口或管理员每天点击。状态`daily-schedule.json`与缓存同目录，在网络请求前原子记下本日尝试；同日重启不会重复采集或编辑。错过09:00时，恢复服务后补一次，下一次仍按次日09:00。失败保留已有缓存，下一天再尝试；状态损坏或无法写入时停止自动采集并继续提供缓存，保留原状态供管理员处理。不会清空付费账本。

调整时间时由管理员修改启动参数并重启既有服务。需要手动补更时先停止既有服务，再在同样的服务用户及配置环境下运行一次`--once`（包含采集和可选编辑），然后恢复服务；不得让两个写入者同时操作同一缓存。首版每次编辑仍最多4篇，其余来源资讯照常展示，不承诺全量AI改写。
